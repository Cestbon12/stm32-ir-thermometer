# STM32 红外温湿度传输

两块 STM32F103C8T6 之间用红外做单向数据传输：发送端读 DHT11，编码成 38kHz 红外信号发出去；接收端用外部中断解码，把温湿度显示在 OLED 上。

整个链路没有用现成的红外协议库（NEC 那一套只发按键码，装不下自定义数据），协议是自己定的。

## 硬件

| 发送端 | 接收端 |
| --- | --- |
| STM32F103C8T6 最小系统板 | STM32F103C8T6 最小系统板 |
| DHT11 温湿度传感器（PB0） | 红外接收头 HX1838（PA0） |
| 红外发射管 / 发射模块（PA0，TIM2_CH1） | 0.96" OLED（PB8/PB9 软件 I2C） |
| 0.96" OLED（PB8/PB9 软件 I2C） | |

## 通信协议

帧格式参考 NEC，但把数据段换成了自己的：

```
引导码   9ms 载波 + 4.5ms 空闲
字节0    帧头 0xA7
字节1    温度整数（°C）
字节2    湿度整数（%RH）
字节3    CRC-8，多项式 0x07，对字节 0~2 计算
结束     560us 载波
```

- 每个字节低位在前
- 逻辑 0 = 560us 载波 + 560us 空闲
- 逻辑 1 = 560us 载波 + 1690us 空闲
- 载波 38kHz，占空比 50%
- 发送端 DHT11 连续读失败时，温湿度都填 0xFF，接收端显示 `Sensor Err`

`Ir_proto.h` 两端共用同一份，改协议只改这一个文件。

## 发送端实现

- TIM2 CH1 输出 38kHz PWM 做载波，`TIM_ForcedOC1Config` 强制输出低电平来关载波，比开关定时器快得多
- TIM3 做 0.5ms 自由计数器，发送周期按 tick 卡，不用 `Delay_ms` 硬等，读 DHT11 的 25ms 塞在两帧之间
- DHT11 用 DWT 周期计数器做微秒延时，读的时候关中断，读完立刻放开
- 连续 3 次读失败才判定传感器故障，偶发一次失败继续用上一次的值
- 独立看门狗 2 秒

## 接收端实现

- PA0 双边沿触发 EXTI0，中断里量相邻两个边沿的间隔，用四状态状态机把 32 位拼出来
- 只量间隔不看电平，所以接收头输出是高有效还是低有效都不用管
- 解码全在中断里做，主循环刷新 OLED 不会漏帧
- 每个脉宽都做容差判断，任何一段不对立刻复位状态机
- 收到帧后校验帧头 + CRC-8 + 数值范围，坏帧计入 `g_BadCnt`
- 300ms 收不到有效帧判定断链，OLED 显示 `No Signal`
- OLED 加了显示缓存，数值没变不重刷

## 编译

Keil MDK5 打开对应目录下的 `project.uvprojx`，直接 Build。工程用 STM32 标准外设库（不是 HAL）。

`Objects/`、`Listings/` 是编译产物，没有提交。
